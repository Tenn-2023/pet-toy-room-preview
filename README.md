# 谁把玩具弄乱啦？

60关竖屏 Canvas 2D 微信小游戏原型，完成前10关后解锁逐步进阶的无尽模式，包含六个章节、27款玩具、六只固定宠物和持续动画客厅。浏览器与微信版本共用 TypeScript 规则、关卡、绘制、能量、存档及广告奖励逻辑。主循环是整理共享玩具并自动交付，不含喂食反馈、商店或装修系统。

所有挑战关的通关提示按“比格、西高地、泰迪、布偶猫、萨摩耶、橘猫”六关一轮，60关中各出现十次，相邻关不重复。确认好的GIF转为透明PNG帧图循环，泰迪按0.9倍速播放，其余按原时长循环（橘猫采样至20fps），只在通关时加载当前一只，内存仅保留当前动画；尺寸保持原比例。原始GIF保存在 `output/`，帧图配置见 `src/win-animation-assets.json`。

## 运行与构建

需要 Node.js 22.12+。

```sh
npm ci
npm run dev
```

浏览器试玩地址为 `http://127.0.0.1:5173/`。首页视频循环播放，点击右下角开始或续玩；首页右上角为“玩具图鉴”，“房间太乱啦”默认进入主线（续玩未结束主线，否则开始当前已开放关卡），不显示道具数量，关卡选择下方为无尽模式入口，无尽成绩仅保存在本机。游戏左上角与通关提示统一使用“回到首页”。拖动下方收纳盒到虚线空位，也支持先点击收纳盒、再点击空位。上方任务卡可查看全部任务；首页“关卡选择”和游戏中的“关卡”按钮打开六个章节的主线关卡选择，可重玩任何已解锁关卡。图鉴按九款一页展示，道具栏及待领取奖励仍可在关卡内查看。

手机试玩：[GitHub Pages](https://tenn-2023.github.io/pet-toy-room-preview/)。独立发布仓库：[Tenn-2023/pet-toy-room-preview](https://github.com/Tenn-2023/pet-toy-room-preview)，与“小狗店长的面包屋”分开。手机竖屏打开；存档属于当前浏览器，激励视频仍为模拟广告。

```sh
npm test
npm run verify
npm run build
node scripts/wechat-smoke.mjs
node scripts/browser-smoke.mjs
```

最后一个命令需要开发服务器运行，仅检查 HTTP 入口与资源；实际交互仍需浏览器试玩。

- `dist/`：浏览器静态构建，通过 HTTP 服务打开。
- `dist/wechat/`：微信小游戏导入测试目录，主包和12个素材分包。
- `npm run build:wechat`：独立构建微信导入包；`npm run build:wechat:release`：检查真实AppID和广告配置后输出 `dist/wechat-release/`。详见 [微信上传说明](docs/wechat-upload.md)。
- `npm run build:pages`：单独构建 GitHub Pages 浏览器版本，使用相对资源路径，输出 `dist/pages/` 并同步到独立的 `deployment/github-pages/` 发布目录；不会改动微信包。
- `src/levels.json`：60关固定任务、障碍、锁栏、初始四盒、随机供给种子和每关两条不同的免费通关路径。
- `artifacts/level-verification.json`：随机、贪心及两步前瞻策略在不同供给种子下的基准结果。
- `npm run levels`：保留各关任务、玩具款式和栏位，将新款加入前三个可选盒，第6关起开局至少两个混装盒；在保存的验证种子下编制并回放两条不同的免费通关路径，全部60关成功后才写入配置。搜索预算内无路径时尝试其他验证种子，只有60关全部有验证路径才更新配置。运行时使用随机种子持续补盒，重开后的后续供给会变化；撤销恢复随机数状态，重复同一步不会重抽供给。历史有限供给生成脚本不再属于当前流程。
- `artifacts/backups/pre-30-level-rework.tar.gz`：改版前源码、脚本和文档备份。

## 视频客厅

客厅使用用户提供的 `output/video-ragdoll/pet_room_ragdoll_carpet-repaired.mp4`，原文件保持不变。运行素材 `public/assets/living-room-loop.mp4` 将1.15倍速度处理进视频时间轴；浏览器和微信都以原生1倍播放处理后的素材，约13.08秒一轮，持续循环、静音。保留704×1472分辨率、H.264／yuv420p、25fps，MP4索引前置以尽早播放。视频1,622,708字节，预览图101,446字节，合计约1.72MB；数据见 `artifacts/room-video-media.json`。

画面等比覆盖420×900设计区域，小幅裁去两侧，不拉伸动物或家具。使用视频自己的完整客厅画面，移除旧房间／动物／挂画叠加；图鉴和任务头像沿用原素材。右下“房间太乱啦”入口以94%—110%持续呼吸缩放，最大尺寸不超屏幕，点击范围同步覆盖放大后的卡片。放置、交付反馈与道具操作通过首次出现时的高亮提示教学，不再设置完整文字规则入口；客厅不显示本局爪爪币，关卡内仍可查看余额。缓冲期间或播放不支持时仍可进入玩法。进入关卡、切到后台时暂停，返回客厅后续播。不会把视频或帧数组写入存档、IndexedDB或微信用户目录；浏览器可以保留约1.62MB视频的正常HTTP缓存，具体清理由浏览器管理。

浏览器用静音inline视频直接绘制到Canvas。视频和预览图使用内容版本URL（当前 `299b4c8d19a0`），避免手机沿用旧素材缓存。微信的Canvas 2D版本使用 `wx.createVideoDecoder` 的按时间戳模式和当前帧缓冲，循环seek；进入玩法或后台后停止并释放解码器及像素缓冲，返回时重新创建并seek到暂停位置。需要宿主支持VideoDecoder与 `wx.createImageData`（后者基础库3.4.10）；旧宿主／解码失败显示预览图。模拟宿主已检查，真实微信开发者工具和真机尚未验证。

重新生成素材需要FFmpeg：

```sh
ffmpeg -i output/video-ragdoll/pet_room_ragdoll_carpet-repaired.mp4 -an -vf 'setpts=(PTS-STARTPTS)/1.15' -c:v libx264 -preset slow -crf 23 -maxrate 1800k -bufsize 3600k -pix_fmt yuv420p -r 25 -movflags +faststart -map_metadata -1 public/assets/living-room-loop.mp4 -y
ffmpeg -i public/assets/living-room-loop.mp4 -frames:v 1 -q:v 7 -update 1 public/assets/living-room-poster.jpg -y
```

## 玩法

棋盘为3列×4行，每关所有栏位都不预放玩具；固定障碍和锁栏保留。全部玩具从底部待放收纳盒出现，由玩家选择收纳盒和可用空位。每盒2行×3格，容量六件；底部显示三个可任选的待放盒及下一盒预览。普通操作不能移动；可使用换位爪交换两个已放盒。

**新收纳盒放下时判定归并；换位爪也可触发两个换位盒的归并。** 规则19以新盒和落位时的上、右、下、左四邻为范围，只整理新盒原有款式，不检查斜角、不扩大到其他旧盒。先比较四邻不同的成对整理顺序，再执行完整计划；各邻盒最多处理一次，新盒清空或交付后结束。旧盒玩具进入新盒后留在新盒，不能再经新盒转去另一旧盒；新盒原有玩具仍可进入直接相邻的旧盒。

两盒有同款时允许搬运及必要交换。保留“两盒能够分成两个不同款单款盒时优先分开”的规则，在此约束下先交付、集中同款、减少混装；成对整理结果同等时，数量归属与原同量偏好优先于腾空盒子。整体仍比较四邻整理后的集中程度、混装、占格和搬动。允许新盒的零散玩具提前为后续同款集中腾位；旧盒里未参与同款合并的玩具不能仅为了腾空位置而搬走。每个搬运及交换步骤都不超过六件；六件同款自动交付。普通单邻盒“新盒2件＋旧盒2件”保留原来的旧盒归属，没有新增“同量强制进新盒”规则；多邻盒中留在新盒的结果由整体计划、容量和不跨旧盒限制决定。

动画教学：首关操作提示统一为“选这个盒子，放到红色框内”，首次小字“点击或拖动都可以”保留，提示框分别贴近当前待放盒与目标空位，并随步骤移动，以红色流动虚线箭头连接目标红框；使用原创手绘点击手势及红色流动虚线，首次提示点击、拖动均可。仅教学放置时同款玩具轻微发光，玩具按实际方向移动，不绘制移动方向箭头；多个邻盒时给先处理的盒子描边，显示“同款最多，先整理这里”或同量短提示。普通操作及跳过教学后的自由操作不显示这些效果，也不增加教学预览等待。网球交付后继续引导白球盒、白球加骨头的混装盒和骨头盒，配简短小字；混装实操单独记录完成状态，旧文字提示或网球后重开不会跳过。交付与剩余委托提示自动继续，任务卡进度随交付动画结束更新。图示示例固定为已确认版本，随机供给机制保持。开发预览入口 `/?previewMotion=priority` 显式启用教学演示，可切换同款、混装和多邻盒反复播放；`/?previewGuide=1` 可重新体验短教学。两个入口使用独立内存存档，预览控件不进入正式构建。

例如旧盒3球＋1逗猫棒＋1蓝鱼，新盒2球＋1逗猫棒＋1蓝鱼＋1小鼠，得到旧盒5球、新盒2逗猫棒＋2蓝鱼＋1小鼠。左侧旧盒2球＋1胡萝卜、右侧旧盒3球，中间放入2球＋1胡萝卜，先将球并入右侧，再将胡萝卜分成单款盒，最终左侧2球、中间2胡萝卜、右侧5球。旧盒2飞盘旁放入3飞盘＋1球，仍为旧盒1球、新盒5飞盘；旧盒5球＋1花生旁放入3球，仍可凑满6球交付，新盒保留2球＋1花生。

两盒各2鼠＋1飞盘时，得到旧盒4鼠、新盒2飞盘。右侧旧盒2球＋3飞盘，左侧放1球＋1飞盘，得到左3球、右4飞盘。左上旧盒3球＋3飞盘，右上放2球＋1飞盘，得到左上5球、右上4飞盘，右下1球与左下花生保持不变，不合计跨盒交付。

四周竞争示例：上方1只小鼠、左侧4只小鼠、下方2个飞盘，中间放入2只小鼠＋2个飞盘；先处理左侧，6只小鼠交付，上方1只不变，下方变成4个飞盘，中间撤走。

六件同款自动交付，空盒撤走并释放位置；这些动作不会触发旧收纳盒再次归并。已经入场的两个同款收纳盒，即使在其他收纳盒交付、撤走后仍在场或出现可归并空间，也不会自动合并，必须由下一次新收纳盒落位触发它与四邻之间的判定。

合并与双向交换动画按每件玩具的实际原格子和接收格子绘制，数量与搬运事件一致；飞行时不重复绘制原位玩具。轻微弧线垂直于真实移动方向，向上、下、左、右的进度均不反向，最后落入实际格子；不再统一先朝上弹、飞到盒中央再跳到最终格子。动画只改变表现，不改变合并结果、容量、交付和撤销。

普通关卡达到全部款式的整理目标立即通关，允许棋盘和待放区仍有玩具。通关前，每次摆放后持续随机补充待放收纳盒，保持三个可选盒及一个预览；不会因供给用完结束。一次摆放归并完成后，所有可用栏位全满且目标未完成，判失败。障碍和未解锁栏位不算空位。

完成挑战1—10关后解锁逐步进阶的无尽模式。每交付六件同款得100分，没有通关目标；无障碍、无锁栏、无爪爪币，12格全部可摆放；补盒只抽取主线已解锁款，优先支持当前款式，混装随交付递进。单次摆放交付2组额外加50分、3组加100分，每多1组再加50分，与原联击奖励叠加。每种道具每局可使用3次。栏位全满时进入可救场的失败面板；炸弹、换位爪或撤销可继续同一局，不立即结算。每次破纪录立即刷新并保存本机最高分，撤销或中断也不降低已达到的最高分；结束、重开或主动返回时结算挑战局数。旧交付组数按100分／组迁移。无尽最高分和挑战局数保存在当前设备，不上传成绩；无需账号、排行榜接口或后端服务器。普通关卡与无尽模式分开选择，未解锁关卡不可挑战。

不再显示完整文字规则。高亮教学提示点击／拖动放置、道具操作、占位限制和交付反馈；首关首次混装合并时展示用户确认的邻盒处理顺序，不在网球阶段或后续补骨头时重复，也不在交换后弹合并规则。首关依次引导2、3、1件网球，第二步已有2件移到新放3件的盒中，第三步集齐六件交付并提示“集齐6件啦！成功交付，任务进度增加。”；随后继续引导放入4件白色绳结小球、2件白球＋1件骨头咬胶的混装盒，再补5件骨头咬胶，直到白球与骨头都成功交付一次。教学结束时提示“还有一个小委托未完成哦！”，单独高亮实际未完成的任务卡，并用上下摆动的手绘箭头指向它；确认后自由完成剩余一组骨头任务，不增加额外弹窗，已确认教学不会重复。操作提示使用红色流动虚线，可点击或拖动；中途退出能继续未完成步骤，也可跳过。教学队列单独标记在本局随机流中，普通关卡供给和全局合并规则不变。提示框按提示词的行数缩小。杂物、锁栏、混装及道具首次出现时分别提示；新款介绍标题为“解锁新玩具！”。第1—20关每关有新款，第21—30关使用已解锁玩具增加混装、任务组数及规划难度。

整理目标逐关增加：第1关4组（24件）、第10关14组（84件）、第20关26组（156件）、第30关40组（240件）。这些是目标交付件数，不是供给上限；各款目标分别统计，超额交付不会替代其他款式。难度同时通过混装供给、同款分散和提前规划提高。每关在默认种子下验证了两条不同的免费解法，不代表每个随机种子和每个中间状态都保证可解。程序策略结果见验收记录，后期难度较陡，仍需真人试玩调校。

供给混装逐步增加：前五关最多两款；第6关起少量三款，第16关起少量四款，后期提升复杂混装占比。盒内有2—4件，后期部分四款盒为5件；支持1＋2、1＋3、2＋2、2＋1＋1等组合，并随机排列。第6关基础混装概率约62%，空棋盘1024盒采样混装率62.9%（旧供给相同采样为14.5%）；这不是玩家通过率。

新解锁款式从开局可选盒出现，尚未发放的参与款式优先进入供给；权重按任务量、累计发放和当前场面平衡。只剩一两款未完成目标时保留其他款作为混装搭配，避免末尾全是同款纯盒。后期场上及待放区已有八款未完成玩具时，暂停引入未出现的新款，完成部分目标后继续加入；三款盒需要至少四个空位，四款盒需要至少六个空位，拥挤时改为两款混装，并适度提高已在场的可归并组合权重。混装补盒算法不变。当前合并规则版本19、奖励规则版本3、挑战栏位版本3；16—18版进行中局兼容保留，其他旧版按原有免费重开方式迁移。

第6关首次出现杂物及爪爪币锁栏，但并非每关都有：纯混装关卡与杂物／锁栏关卡交替安排。总棋盘恒定12格；每关锁栏0—3格，杂物与锁栏合计不超过3格。纯混装关卡为1、2、3、5、7、10、13、16、20、23、26；两锁栏关卡15、19、22、25、28；30关三锁栏，其余配置见 src/challenge-layout.ts。30关的默认验证种子均有锁栏未打开时的免费解法，不依赖购买或广告。随机生成的玩具逐件计入已发放账本，检查在场、待放及已交付数量与账本一致。

普通关卡爪爪币从第6关开始，只有标有奖励的三项任务会发币。奖励任务交付1组自动到账，无需等待整项任务完成；每项每局一次，后续完成整项不重复支付。普通搬运、额外交付和通关不另发币。有锁栏的关卡总奖励为全部锁栏费用＋8币，两项主奖励各一半总解锁费用，另有一项8币；无锁栏关卡不发币。一个8币锁栏总奖励16币，两个12币锁栏总奖励32币，三个16币锁栏总奖励56币。奖励任务优先显示，清单明确写出“1组奖励4”等节点（所有奖励门槛均为1组）及黄色透明底爪印；本关获得总额与可花余额分开统计，花币不会重置领奖资格。奖励节点随免费验证路径检查首个锁栏在前中期可解锁，全部锁栏费在胜利前攒够；这是验证种子的样本，不承诺每个随机局同样时机。无尽模式只计分，不发币或设锁栏。币只属于当前局，重开、重玩或切关从0开始，栏位重新锁定；续玩同一局恢复原状态。锁栏价格按第6—10／11—20／21—30关分别为8／12／16枚，点击显示价格确认和余额。满位失败允许用已赚币解锁继续，不再次扣能量；无尽满位可用道具或撤销救场，结束或重开时结算。撤销恢复摆放前币数和栏位，包括之后发生的购买，不可重复刷币。

锁栏位置按关卡编制，不固定在底部：前期以角落保留连续空间，中期使用侧边，后期部分锁栏占中间、影响盒子邻接路线。第6关锁右上角，第12关锁第二行左侧，第17关锁第二行中间，第30关锁右上角及第二行中、右侧。布局在重开时保持；关闭全部锁栏时可用空间仍连通，每关仍验证两条不购买栏位的免费路径。

## 能量与存档

- 初始10点，上限20点；开始、重试和重玩关卡各消耗1点。
- 失败不额外扣除；首次通关返还2点，重复通关返还1点，实际到账受上限限制。
- 开始或重试无尽模式消耗1点；失败和主动结束不返还能量，续玩同一局不再次扣除。
- 每15分钟自然恢复1点，离线有效；满能量停止积累，不储存额外恢复时间。
- 完整观看视频增加3点，满能量时不请求广告。
- 续玩、返回客厅、前后台切换及撤销不再次消耗能量；能量为零时仍可继续已有的一局。

本地单一存档保存能量、首次通关、当前局（含本局币、栏位、待放盒、随机数状态、发放账本）、最近50次完整摆放快照、图鉴、音效和无尽最高成绩／局数。最后一步动画中退出也能恢复通关；无尽满盘重载仍可救场，结束后才结算，不重复领奖或计局。图鉴按主线到达的关卡显示“已解锁／未解锁”，与无尽供给共用同一进度；旧无尽的已见／交付标记不会提前开放后期款。所有27款保留名称和大图查看，未解锁款淡显。旧版本只迁移已收纳的旧12款及音效，30关进度从第1关开始，10点初始能量只授予一次。

挑战栏位或无尽规则更新时，进行中的旧版本局免费从该关重新开始，保持能量、已通关进度、图鉴与最高分。已有存档的关卡和图鉴进度保留，不补发历史币，也不恢复跨关币库或永久栏位。整理规则更新后，进行中的旧版本局免费从当前关卡重新开始，清空旧撤销和本局币、恢复初始锁栏，不再扣能量；当前版本存档继续原局。玩具编号稳定，图鉴中的两款玩具同步换图、换名。

当前存档是客户端原型，不含服务器校时或防作弊。开发环境暴露调试入口，生产构建不暴露。

## 激励广告

原型明确使用模拟广告，提供完成、取消、加载失败三个分支。换盒按钮为“▷ 刷新待放列表”，仍通过视频领取；空位剩一两处时提示换盒／撤销，失败面板保留视频撤销入口。已验证刷新在模拟视频面板显示下一步可交付、释放空位或归并的实际收益；本地记录入口点击、候选验证、广告结果与应用结果，供后续评估使用。真实观看率、留存和收入尚未测量。每局一次免费撤销，随后最多3次成功的视频撤销，每次退回一张完整摆放快照，连续两次回退两步，取消／加载失败不占次数；撤销恢复摆放之前的供给、连锁、交付和空盒回收，能量、免费次数和广告撤销额度不回退；本局爪爪币和锁栏按摆放前的快照恢复。

炸弹与换位爪均为原创Canvas图标，不使用emoji；各最多持有1个、可跨关保留并保存本机，广告完整观看成功后才领取，取消／失败／重复或过期回调不发奖。

- **炸弹**：满位失败面板可看视频领取，使用时选择一处杂物或未完成的收纳盒清理，不清锁栏。清理玩具不交付、不发币、不触发旧盒合并；废弃件数记入账本，已发放数量仍守恒。清理只改变本回合，重开恢复原始杂物布局。
- **换位爪**：有两个已放盒时可看视频领取。选择两个不同的盒子，先一起交换位置，再处理第一选中盒的新位置、随后处理第二盒；盒子若已交付或清空则跳过。仍使用四邻数量优先和六件容量规则，换位交付可正常计分及支付任务奖励。
- 两个道具使用后清空此前撤销记录，后续摆放照常撤销；撤销不退还道具。满位救场不重复扣能量，库存满时不再播放领取广告。

任务栏隐藏动物品种文字，只保留头像和玩具图片；卡片每页六款，更多款式可翻页，整项清单可点击查看。奖励显示“奖励4”＋原创爪爪币图标，旁边标注奖励所需组数；奖励达成后为“已获4”＋同图标。第8关保持6款／12组，其中白绳结1组、丝瓜络鱼2组，本来即属于任务。第6—10关仍有至少两款未完成时停止新发已完成款；最后一款收尾仍混装，但只搭配1件其他玩具且盒长至少3。第8关三款混装分支从17.6%降为10%，保留两款主结构，不增加品类或目标。

“刷新待放盒列表”在广告前准备并缓存一条最多使用当前三个新盒的交付路径，交付必须消耗原场上的玩具；包括委托已经完成的同款，不依赖新盒相互交付兜底。不验证整关或严格更优，不显示验证过程或先腾空位等拒绝提示。优先重新分配已有供给，必要时补足相邻旧盒缺少的已解锁同款，单盒最多五件；视频完成后应用已验证且不同的新列表。棋盘、任务、杂物、锁格、纸团、爪爪币、步数、下一盒预告与随机数保持不变，更新发放账本；成功后清空旧撤销记录，取消或失败保留供给。

没有旧玩具或旧盒与所有空位隔离时刷新入口不可用，不播放广告。满格沿用失败流程，使用道具或撤销恢复空间后重新判断刷新条件，失败卡不增加刷新说明。短路径搜索最多展开3000个状态，随后尝试定向补足并回放验证；未加入整关后台搜索或改写后续补盒。过期的棋盘回调不会应用旧候选，能量视频奖励属于全局进度。
